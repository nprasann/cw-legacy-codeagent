How It Works

Three agents · Eight skills · One knowledge base

Specialized agents that compose. Deterministic routing. Reusable skills. A grounded knowledge base.

@legacy-code

LegacyCodeAgent

Reads & explains legacy source. Builds division maps, control-flow diagrams, modern analogies. Comprehension-only — never editorializes.

Boundary: doesn't score quality. Delegates to @review.
@knowledge

KnowledgeAgent

Grounds answers in tribal docs, runbooks, SME interviews. Cites every claim. Refuses to fabricate when no source exists.

Boundary: never asserts a fact without a citation.
@review

ReviewAgent

Legacy-aware code review. Scores modernization by value × blast-radius × effort. Veto authority on do-not-touch.

Boundary: delegates explanation to @legacy-code.

Key Features

Five things make this different

🎯

Built for legacy

Not a generic "explain my code" tool. Calibrated for COBOL idioms, Struts 1 quirks, T-SQL pathologies, batch blast radius.

📎

Cited, not invented

Every claim links back to /knowledge. grounded · partial · inferred labels on every answer.

🛑

Veto rules

do-not-touch invariants are honored, not ignored. The agent literally cannot recommend a violation without a documented mitigation.

## Magic Status Codes

| Code | Meaning              | Source       |
|------|----------------------|--------------|
| A    | Approved             | inferred     |
| R    | Rejected             | inferred     |
| H    | Hold (standard)      | inferred     |
| Z9   | Special hold — legal review | cited ↓ |

[knowledge/tribal/nb-post-z9-special-hold.md#rule]

Confidence: grounded

Gaps:
• No characterization test for Z9 branch
• SME interview re: 'H' vs 'Z9' boundary

✓ grounded

Fully cited. Every claim links to a source. Compliance can audit.

~ partial

Some citations, some inference. Mixed evidence — read carefully.

! inferred

No source. Treated as a hypothesis. Gaps section tells you what to write.
